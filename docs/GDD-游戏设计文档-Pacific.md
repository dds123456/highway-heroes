## 1. 产品定位与范围

一句话：在自然光照的公路嘉年华中，驾驶可换装的摩托车，通过走线、漂移、氮气和道具竞争名次，也可以挑战圈速或自由巡航。

品类为浏览器 3D 街机摩托竞速，不是硬核摩托模拟器。当前优先交付 Windows 桌面 Chrome / Edge 本地单机体验；保留键盘、标准手柄和触屏输入实现，真实手柄、真实移动设备与其他浏览器仍需专项验收。

### 1.1 设计支柱

1. **驾驶节奏清晰**：弯道、漂移蓄能、加速带与道具位置形成连续决策，速度感由车辆、镜头与声音共同表达。
2. **自然场景、明确交互**：自然道路材质与日光为底；光晕只突出道具、加速带和装备识别，不把整个世界变成霓虹场景。
3. **角色可辨认、外观不影响公平性**：男女基础轮廓、体型、面容与衣着可编辑，但不改变碰撞尺寸和驾驶性能。
4. **规则可解释**：导弹优先前方目标；下雨逐渐出现；完赛后车辆停下并及时结算。
5. **浏览器可交付**：提供源码、正式网页与独立 HTML；性能以可复现测量判断，不用主观完成百分比代替验收。

### 1.2 参考方向与实现边界

| 方向 | 当前采用的设计语言 | 不属于当前成果 |
|---|---|---|
| GTA5 风格方向 | 都市公路、自然材质、成人比例车手、分类角色编辑 | 原版资产、同等级真人模型、犯罪系统、城市 NPC 模拟 |
| 地平线系列／用户提出的地平线 6 方向 | 公路嘉年华氛围、赛事与巡航并列、车辆展示和清晰活动入口 | 原版地图、无缝开放世界、完整嘉年华生涯 |
| 黑红赛博定制 | 88 号码、玉鑫1号标识、局部赛博头盔与车衣 | 全世界赛博朋克化、自由上传贴花编辑器 |

以上是本项目的美术目标，不是对参考游戏具体功能的描述。素材应保持原创或使用权可确认；本次没有提取参考游戏资源。

### 1.3 当前范围

已实现四种模式、三种车型、三套赛道主题、角色工作室、四类携带道具、固定加速带与障碍、随机渐变阵雨、本地成绩与计时赛幽灵车。

当前没有开放世界探索任务、经济商店、生涯成长、联网实时竞速、动态布料、真人扫描皮肤或完整损伤系统。保留原平台接口不等于上述联网功能已经验收。

## 2. 核心循环与玩家流程

主菜单选择模式 → 车库选择车辆与外观 → 选择路线并确认组合 → 倒计时 → 驾驶／漂移／加速／道具 → 结算与记录 → 再来一局或返回菜单。

角色工作室是主菜单的独立入口：进入时创建编辑草稿，只有「保存角色」才确认；「取消修改」返回原外观。保存后的角色用于车库和比赛。

### 2.1 模式规则

| 模式 | 对手 | 结束条件 | 携带道具 | 目标与记录 |
|---|---:|---|---|---|
| 竞速赛 RACE | 3 名 AI | 完成 3 圈 | 开启 | 最终名次、总用时与有效圈速 |
| 计时赛 TIME TRIAL | 无 | 完成 3 圈 | 关闭 | 挑战最佳有效圈速，记录／回放幽灵车 |
| 漂移赛 DRIFT | 无 | 90 秒耗尽 | 关闭 | 漂移积分与连击，保存成绩 |
| 自由巡航 CRUISE | 无 | 玩家主动退出 | 关闭 | 驾驶练习，无比赛胜负与限时 |

“携带道具关闭”指四类可拾取后使用的道具，不表示路面的加速带与障碍被移除。计时赛与竞速赛的实际时长由驾驶决定；原 GDD 的 3–6 分钟只可视为体验目标，尚无用户测试统计。

## 3. 摩托车、车衣与驾驶

### 3.1 当前车型

| 游戏显示名 | 内部 ID | 外观定位 |
|---|---|---|
| Cafe Custom 88 | bonneville | 复古街车、外露机械与短车尾 |
| Desert Scrambler | dt1 | 越野／攀爬车轮廓、高离地感 |
| RS Sport 200 | flh | 全包围运动跑车轮廓 |

内部 ID 为兼容历史代码保留，不代表模型仍是原同名量产车型。当前比赛使用新的程序化 Three.js 分部件网格，不是原 Cafe Race／Yamaha／RS200 CAD GLB 的精修拓扑版本，也没有新增导出的 GLB。

模型区分漆面、金属、橡胶、皮革、玻璃；包含独立轮组、刹车盘、发动机、排气、座垫、灯具等。车轮随速度旋转。每车提供四套基础配色，并保留车衣开关；车衣主要作用于漆面件，不应把轮胎和机械部件一起染色。

黑红哑光、白色 88 和玉鑫1号作为定制识别元素保留。各车车衣布局按部件适配，不承诺任意 GLB 自动贴合或在线任意文字编辑。

当前车衣显示名分别为 Cafe 的 Cyber Matte 88、Desert 的 Sunset Classic 07、RS 的 Volt Division 27，资源对应 `cafe-race-cyber-wrap.png`、`yamaha-sunset-stripe-wrap.png`、`rs200-electric-blue-wrap.png`。这些是现有预设命名，不表示三套车衣都改成同一号码或同一配色。

### 3.2 操控规则

车辆沿赛道样条维护纵向进度、横向位置、速度、倾斜与腾空等状态。使用街机化加速、制动、风阻、漂移与碰撞，不模拟真实轮胎温度、发动机挡位或完整悬挂动力学。

| 项目 | 当前代码值／规则 | 说明 |
|---|---|---|
| 世界基础最高速 | 94.44 m/s，约 340 km/h | 实际还受车辆运行时倍率及加速状态影响，不把车库展示评分当物理单位 |
| 漂移触发 | 非腾空，速度 >36 m/s，转向绝对值 >0.4，且按漂移或转向绝对值 >0.82 | 需要一定速度和转向 |
| 漂移蓄能 | 每秒 +0.16；非漂移时每秒 -0.12，限制在 0–1 | 蓄能不是永久库存 |
| 手动氮气 | 蓄能 ≥0.98、油门与氮气同时输入、当前无加速计时 | 持续 2.4 秒并清空蓄能 |
| 加速拾取 | 速度 +14 m/s，受上限限制；加速计时至少 2.4 秒；蓄能 +0.25 | 加速带和加速道具调用同一效果 |
| 障碍命中 | 速度保留 25%，冷却 1.5 秒 | 腾空与冷却中不执行该命中惩罚；横向推离视来源而定 |

这些是实现基线，不是经过平衡测试证明的最佳数值。本次 GDD 更新不调整手感或数值。

## 4. 角色工作室与拟人化

### 4.1 功能结构

| 分类 | 当前内容 |
|---|---|
| 基础脸型 | 四种原创基础：棱角型、柔和型、修长型、宽颧型；选择 A/B 并混合 |
| 五官 | 12 项：鼻翼宽窄、鼻梁突出、嘴唇厚度、脸型宽窄、脸长、下颌宽、下巴长、脸颊饱满、额头高、眉骨深、眼距、嘴宽 |
| 体型 | 10 项：身高、肩宽、胸廓、腰围、胯宽、肌肉量、手臂比例、腿长比例、头身比例、颈部宽度 |
| 外观 | 6 种肤色、4 个发型选项、5 种发色、4 种瞳色、3 档胡须、2 类服装、4 种衣着配色 |

男女选择在各分类顶部可见。身高范围为 165–190 cm；其余参数按各滑杆范围限制。脸型混合是原创美术参数插值，不是族裔判断或真实遗传模拟。

### 4.2 男女外形规则

选择性别改变基础面部、肩腰胯与四肢比例，不只是切换文字标签。女性版本调整下颌到颧骨过渡、胸腰连续衣着曲面、腰胯轮廓和手掌比例；保留防护服覆盖与运动员体态，不以夸张裸露表现差异。

男性发型为寸头、短侧分、后梳、光头；女性选项为利落短发、齐颈侧分、低束马尾、光头。齐颈发型使用连续发片，马尾为几何体体积，不是逐根毛发模拟。眼白缩小、眼睑增加厚度、鼻口与皮肤色差收敛，用于减少木偶感。

性别切换保留现有滑杆、颜色与衣着，不建立两套独立存档。旧数据缺少性别时默认男车手；保存仍使用同一个角色档案。

### 4.3 预览、编辑与持久化

- 三档取景：全身、上半身、头部；支持正面、侧面、背面、拖动旋转和自动旋转。
- 支持随机角色、恢复默认、滑杆单项重置、最多 40 次参数更新撤销、对比已保存角色。
- 对比只切换显示对象，不覆盖草稿；取消不写入角色存档。
- 存档键为 `hh.character.v1`，兼容旧 `hh.face`。非法、缺失和非有限数值使用默认或范围钳制。
- 存储被浏览器禁用或容量不足时，不能保证跨刷新保存；本地存档不等于云同步。

### 4.4 骨架、骑乘与头盔

人物保留 17 个兼容控制关节；头部、躯干、手臂、腿部等为关节附着网格。按体型调整座位与手脚约束，使用逆向关节求解保持手握车把、脚靠脚踏。工作室有轻微呼吸与转头待机，不代表已经加入完整面部表情或全身肌肉蒙皮。

赛博头盔采用 YX-01 全盔：哑光黑切面外壳、青色窄视窗灯带、下颌装甲、通风口和红色尾灯。男女共用并随头部比例缩放；比赛默认佩戴。工作室「头盔预览」开启时隐藏头部／头发，避免穿盔。

### 4.5 品质边界

当前为轻量程序化风格化人物。尚无真人扫描皮肤、精细毛孔与布料贴图、真实毛发、表情骨骼、动态布料或完整柔性蒙皮。近景仍有简化的耳鼻口和发片结构，不能写成“已达到 GTA 级写实人物”。

## 5. 赛道与环境

| 路线 | 内部 ID | 环境表达 | 常规天气 |
|---|---|---|---|
| 海岸都会环线 | meadow | 海岸城区、棕榈、道路基础设施 | 干燥开局与随机阵雨 |
| 荒漠州际公路 | canyon | 荒漠山体、稀疏植被、公路设施 | 干燥开局与随机阵雨 |
| 高山隘口 | snowfield | 雪山、针叶树、寒冷色调 | 保留下雪 |

现有三套路线选择与闭合赛道系统保留，本轮没有把它们连接成一个开放世界，也没有重新设计线路形状。道路采用样条采样、分块显隐；环境采用实例化和材质合批减少重复物体开销。世界配置的流式半径为 620 m，道路半宽为 9 m。

视觉重点为沥青、标线、路肩、护栏、路牌、灯具、房屋、树木与远景层次。场景装饰不应抢占道路中央的驾驶视野。雪山等远景应保持轮廓可读，不能因雾与雪粒子遮住路线。

## 6. 比赛与 AI

起跑倒计时为 3 秒。每圈设 8 个顺序检查点，记录单圈有效性；比赛进度按圈数与赛道进度计算排名，有效圈用于圈速记录。

实现边界：当前过线推进圈数与检查点有效性是分开处理的，不应宣称已经具备完整反作弊或所有跳检查点行为都会阻止完赛。正式排行榜需要进一步审核有效性和服务端校验。

竞速赛使用三名 AI，沿用激进、稳定、飘忽的驾驶性格及前瞻转向、避让和追赶机制。本轮没有重做 AI 超车博弈；只是统一了导弹选敌规则。AI 不代表在线真人玩家。

### 6.1 完赛与结算

1. 玩家完成最后一圈时记录总用时与最终名次，速度立即归零，冻结车辆位置。
2. 从冲线算起经过 **2 秒有效游戏时间**后弹出结算，不等待 AI 全部完赛；正常运行时以满足用户要求的 3 秒内结算为目标。
3. 暂停会停止这段游戏计时，低帧率、后台标签页也可能使逻辑时间落后，因此不是浏览器墙钟时间的绝对 3 秒承诺。
4. 结算状态停止比赛物理、道具推进和比赛计时；镜头、界面等展示可以继续刷新。
5. 漂移赛由 90 秒耗尽触发结算，不采用“三圈冲线”的触发条件；巡航不自动结算。

验收失败条件：冲线后继续自动油门前进、等待全部 AI 才结算、重复发完赛事件、结算后成绩继续变化。

## 7. 道具与加速带

### 7.1 拾取与库存

竞速赛默认布置 10 个道具拾取点，按四类道具循环分配，不是每次打开随机宝箱。拾取后该点隐藏并冷却 4 秒；每辆车只有一个道具槽，新拾取会替换原槽。玩家按使用键触发，AI 沿用原有使用时机逻辑。

| 道具 | 视觉识别 | 当前作用 |
|---|---|---|
| 导弹 | 橙色光晕、尖头长弹体、四片尾翼、喷口与尾焰 | 自动选择一个目标，沿道路追踪 |
| 护盾 | 蓝色护甲板／光晕、车身护盾气泡 | 持续 5 秒，当前拦截导弹 |
| 加速 | 青色氮气瓶与光晕 | 触发加速拾取效果 |
| 地雷 | 洋红识别色、立体雷体、部署后的范围圈 | 后方部署，0.7 秒后激活，18 秒后到期 |

护盾没有接管地雷和普通道路障碍命中逻辑，不写成“免疫所有伤害”。地雷不攻击部署者。导弹与地雷命中复用障碍减速机制，而不是生命值扣血系统。

### 7.2 导弹选敌规则

对玩家和 AI 使用同一规则：排除自身和已完赛车手 → 优先前方最近者 → 前方无人时选择后方最近者 → 没有任何有效目标则不发射、不消耗导弹。

“前后”按环形道路的最短有符号纵向距离判定，不按排行榜名次，也不按摄像机屏幕位置。超过半圈的正向距离会折算成负向距离；起终点交界仍可正确选敌。恰好同进度或半圈距离按当前算法归入前方。

飞行速度为 150 m/s，最大累计航程为 700 m；目标选择没有先做 700 m 射程筛选，因此成功锁定不保证命中。导弹横向追踪已选目标，不是自由空间寻路；目标后来完赛不会重新选择其他目标，到航程上限后清理。命中判定采用道路纵横距离阈值，不是精确网格碰撞。

### 7.3 加速带与障碍

默认 12 块加速带，沿路交替横向布置；每块触发冷却为 2.6 秒。使用抬高的流动箭头、青色侧灯、局部光晕和触发亮度变化，保留实体底座轮廓。

默认 14 组道路障碍，主要为中空轮胎、带箍油桶与路障。碰撞判定尺寸沿用原逻辑，美术几何的增加不应扩大处罚范围。

### 7.4 可读性要求

光晕采用局部透明渐变、光圈与窄尾迹，不依赖全屏 Bloom。类型同时通过颜色、形状和 HUD 文字表达。高速、阴影、雨天及雪地都应能区分道具与背景；光晕不能遮盖整辆车或穿透一切遮挡来造成误导。远距与色觉可访问性仍需更完整实测。

## 8. 随机渐变天气

非雪地使用按时间循环的阵雨，不再按固定路段突然切换雨／雷暴。雨量强度为 0–1 的连续值。

| 阶段／参数 | 当前规则 |
|---|---|
| 初始干燥阶段 | 35–75 秒随机 |
| 雨期目标 | 每次随机强度 0.35–0.85 |
| 雨期长度 | 30–70 秒，包含渐强过程 |
| 后续干燥阶段 | 55–120 秒，包含退雨过程 |
| 最大增雨速率 | 每秒 1/18 强度单位 |
| 最大退雨速率 | 每秒 1/24 强度单位 |
| 重新比赛 | 重置为干燥并重新抽取时序 |
| 暂停／结算 | 天气循环计时停止 |

18／24 秒表示跨越完整 0–1 强度区间的速率，不表示每次都固定过渡这么久。雨量驱动细雨丝数量、透明度、雨声音量、冷色覆盖和水花表现；雨丝使用世界空间细线与轻微风偏。高山路线保留下雪，不套用非雪地阵雨循环。

该系统的当前交付重点是视觉和声音渐变；没有把雨量接入完整的湿路抓地、积水或水漂模拟，不应声称雨天已经改变轮胎物理。

## 9. 美术与渲染规范

当前方向为自然公路场景加局部嘉年华交互信号。旧 GDD 的“零 PBR、硬色阶、双层黑描边、全场荧光轮廓”不再是验收标准。

- 材质：漆面、皮革、金属、橡胶分别表达粗糙度与金属度，避免所有物体同样塑料发亮。
- 光照：自然方向光、柔和阴影、ACES 色调映射、sRGB 输出、远景雾和环境反射。
- 地图：海岸／荒漠／高山有不同地形与植被，不以改变天空颜色冒充主题差异。
- 人物：以成人比例、连续轮廓与衣着结构改善拟人化；性别和体型差异在全身预览与骑乘距离均应可辨认。
- 交互：主场景抑制过量自发光，强调道具、加速带、赛博头盔和必要信号。
- 素材：允许使用原包内纹理和音频，不再要求“全部零外部素材”；新程序化网格和画布纹理由本项目生成。原素材来源与权利仍需在对外发布前核对。

## 10. UI、HUD 与操作

### 10.1 信息结构

首页突出四种模式、进入车库、角色定制、操作说明和设置；成绩与排行榜为次级折叠内容。车库与路线页标记真实步骤，可返回修改；开赛前显示模式、车辆、路线组合。

比赛 HUD 包含速度、圈数／名次或模式目标、计时、氮气／漂移能量、右上小地图和道具槽。道具槽显示持有类型和使用键；中央道路视野优先，不用大面积装饰遮挡转弯判断。

嘉年华界面以深海军蓝面板、浅色文字、洋红主操作、青色交互和暖黄提示为主；角色工作室沿用更中性的深色面板与暖黄控件。两者层级一致，不强行宣称所有页面只有一套强调色。

### 10.2 主要键盘操作

| 操作 | 按键 |
|---|---|
| 转向 | A / D 或左右方向键 |
| 油门／刹车 | W / S 或上下方向键 |
| 漂移 | Space / Shift / X |
| 使用道具 | E / J |
| 氮气 | Q，需同时油门与足够蓄能；手柄 Y 不作为键盘按键 |
| 暂停／返回 | Esc / P；具体返回由当前界面处理 |

输入实现保留标准手柄与触屏支持；不要把桌面模拟窄屏测试等同于真实手机触控、性能和发热验收。

## 11. 声音与记录

音频使用 Web Audio 与原包采样／音乐，不再局限于振荡器合成。引擎随速度和油门变化；漂移、碰撞、拾取、起跑与冲线提供事件反馈；雨声随强度平滑变化。浏览器可能要求首次点击后才能启动声音。

设置提供音效、引擎、天气、音乐音量及转向灵敏度。角色、设置、成绩与幽灵数据保存在当前浏览器；成绩存储 `hh.records.v1` 最多保留 400 条。不同域名、端口、本地文件路径及浏览器可能形成不同存储环境，不能承诺换文件后自动共享所有旧记录。

离线入口没有企业账号菜单，不连接在线排行榜。原平台入口与后端保留，但本轮没有验证认证、服务端成绩提交或公网部署。

## 12. 技术与交付

Three.js 0.168.0 + TypeScript + Vite，原生 DOM / CSS 界面，固定 60 Hz 游戏逻辑步；渲染按帧更新。程序化模型、材质合批、实例化、道路／环境分块及自适应像素比共同控制开销。

| 入口／内容 | 用途 |
|---|---|
| 根目录 Highway-Heroes-Pacific.html | 内嵌所需资源的单文件试玩成品，约 26.6 MiB |
| START-GAME.cmd / serve.mjs | 本机服务，默认 127.0.0.1:5189/offline.html |
| frontend/dist/offline.html | 构建后的离线入口，必须连同 dist 资源目录使用 |
| frontend/dist/index.html | 原平台入口，需要原部署环境，不等同于离线版 |
| frontend/src | 当前可编辑源码 |
| frontend/public | 保留原素材、纹理、音频；旧 GLB 作为源资产保留 |
| backend | 原后端，不代表本轮新增或验收联网功能 |

源码开发在 frontend 目录执行 `npm ci`、`npm run dev`，打开开发地址的 `/offline.html`。`npm run check` 执行类型检查、测试和构建；`npm run build:portable` 同时生成正式网页和独立 HTML。

本次只修订文档，不重新构建或覆盖已经交付的桌面游戏 ZIP／HTML。后续重新打包时应包含本 GDD。

## 13. 验收与质量记录

### 13.1 已有证据

- 人物自然化 V2 实现阶段构建通过；本次 docs 全量同步重新执行类型检查和测试，9 个文件共 46 项全部通过。本次未重新构建成品或开展浏览器视觉巡检，完整记录见 VERIFICATION.md。
- 回归包含角色存档迁移与参数校验、女式发型几何预算、三车型男女高矮车手手脚定位、导弹前后优先、渐变雨和完赛冻结。
- 已有本机浏览器流程与截图验证；最新人物截图为 [头部](../previews/12-female-natural-head.png) 与 [全身](../previews/13-female-natural-body.png)。其他编号截图可能对应更早迭代，不是最新模型证据。
- 美术初版曾在本机短时采样约 57–60 FPS、328–537 次渲染调用（含阴影）；这是旧基线，不是自然化 V2 的最新完整性能报告，也不是所有设备保证。

### 13.2 目标与待验证项

桌面目标是稳定、流畅的 60 FPS 体验；当前不能把旧 GDD 的总调用 ≤200、首屏 ≤5 秒或 Retina 全设备 60 FPS 写成已达成。默认人物自动测试预算为 <75000 三角形、<85 个批次；新增女式发型用例为 <80000 三角形、<90 个批次，包含隐藏部分，不等于全场渲染预算。

| 验收场景 | 判断标准 | 当前证据／缺口 |
|---|---|---|
| 人物编辑 | 男女与体型差异可见，保存／取消／撤销不会误改存档 | 自动测试和桌面预览；极端参数全部组合未穷举 |
| 骑乘 | 三辆车高矮角色手脚定位误差受控 | 回归测试覆盖；极端动作下穿插仍需视觉走查 |
| 道具可读性 | 形状、颜色和提示在移动中可识别 | 桌面观察与几何测试；全天气远距、色觉测试待补 |
| 导弹 | 前方优先、后方回退、跨起终点、排除完赛者 | 规则单元测试；不保证射程外命中 |
| 天气 | 不因进入路段突然下雨，暂停不推进周期 | 时序单元测试；长时间体验与音画同步待扩测 |
| 冲线 | 立即停驶、2 秒有效时间后结算、事件不重复 | RaceManager 回归；完整三圈人工跑圈仍待补 |
| 性能与兼容 | 记录设备、分辨率、画质、帧时间和长时间稳定性 | 真机手机、实体手柄、跨浏览器和长期压力测试待补 |

不再用“人物 82%”“性能 80%”等没有统一量尺的百分比表示完成度。
